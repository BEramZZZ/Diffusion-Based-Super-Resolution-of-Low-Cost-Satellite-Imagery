01The lineage, in one paragraph

SRGAN established that pixel-loss-only training (MSE) produces blurry, PSNR-optimized-but-unconvincing output, and fixed it by adding adversarial + perceptual loss — at the cost of lower PSNR. ESRGAN kept that idea and rebuilt everything around it: a new generator backbone (RRDB) capable of going much deeper without instability, a sharper discriminator (relativistic), and a better-informed perceptual loss (pre-activation VGG features). Real-ESRGAN then made a very specific bet: the generator from ESRGAN was already good enough — what was actually broken was the training data (synthetic bicubic degradation doesn't look like real-world degradation) and the discriminator's resolution (a single whole-image verdict is too coarse once degradation severity varies locally). So Real-ESRGAN changes the data pipeline and the judge, and leaves the generator's core block untouched.

That last point matters a lot for what follows: the exact mechanism that causes hallucination-type behavior in Real-ESRGAN was already fully decided by ESRGAN in 2018. Real-ESRGAN doesn't introduce a new hallucination mechanism — it changes how often and where the existing one gets triggered.

02SRGAN (2017) — where the core tension starts

Grounded

Pre-2017 SR models (e.g. SRCNN) trained with pixel-wise MSE loss, which is mathematically identical (up to a log transform) to maximizing PSNR. This produces the highest possible PSNR — and consistently blurry, over-smoothed output. SRGAN's fix: add a content loss computed in VGG feature space, plus an adversarial loss from a discriminator, on top of a deep residual generator (SRResNet — since fully replaced by RRDB, not worth studying in detail).

Why MSE-only training is forced into blur

The value that minimizes expected squared error against a distribution is that distribution's mean. This isn't a training artifact — it's what the loss function is mathematically defined to produce.

Worked example
One ambiguous patch, two equally likely outcomes

Suppose one ambiguous LR patch corresponds, across the training set, to two equally likely true HR pixel values — 40 (shadow) and 200 (sunlit), each with probability 0.5. The MSE-optimal prediction a minimizes E[(X−a)²] = 0.5(40−a)² + 0.5(200−a)². Setting the derivative to zero gives a = 0.5(40) + 0.5(200) = 120 — a value that never occurs in the real data, but has lower expected squared error than either real outcome because it's equidistant from both.

Multiply this across every ambiguous patch in an image and you get exactly the blurry, under-textured output SRGAN was built to fix. PSNR is not an independent judge of quality here — it's measuring the same quantity the MSE loss was directly optimizing, so an MSE-trained model scoring well on PSNR is not a coincidence. Any other model (adversarially trained, or a diffusion model sampling stochastically) produces one specific sample rather than the mean, and any single sample will almost always score worse on squared error against one specific ground-truth crop than the mean does — even when it looks far more realistic.

Relation to hallucination: this is the origin of the under-invention pole (Section 6) — output ambiguity resolved by averaging it away. It's the opposite failure mode from hallucination, but comes from the exact same root cause: multiple plausible HR patches mapping to one LR input.

03ESRGAN (2018) — the architecture Real-ESRGAN still runs today

Grounded

Three changes, all aimed at pushing harder against the blur from Section 2, plus one deployment convenience.

3a — RRDB: dense connections + residual scaling, no batch norm

Each conv layer inside a dense block receives the concatenation of every earlier layer's output in that block, so low-level detail and gradients have a direct path to every later layer without having to survive re-derivation through many stacked transformations. This is what lets the network go as deep as 23 RRDB blocks (each with 3 nested dense blocks) without gradients or fine detail degrading on the way through.

Batch normalization is removed entirely. BN normalizes each batch using that batch's statistics at train time, then substitutes a running average at test time — for restoration, this creates a mismatch whenever a real test image's local statistics differ from the training-time average, showing up as visible banding/blob artifacts.

Removing BN without a replacement creates a different risk: with residual branches added at full strength and no normalization between blocks, signal magnitude can compound across the stack. If each block's contribution has roughly unit standard deviation, accumulated variance grows like σ√N. For N = 23 blocks: √23 ≈ 4.8× the original signal scale flowing into unnormalized layers — a direct path to unstable training. The fix is residual scaling: multiply each block's output by a fixed constant β = 0.2 before adding it back. Recomputed: 0.2 × √23 ≈ 0.96× — almost exactly back to the original scale, using pure arithmetic instead of a data-dependent normalization step.

3b — Relativistic average discriminator (RaGAN)

A standard discriminator predicts "is this real or fake" in isolation. Once the generator gets good, its gradient on real images saturates — there's nothing left to learn from that side, and training stalls. RaGAN instead predicts something relative: is the real HR image more realistic than the fake one, on average, and vice versa. This keeps producing a useful gradient throughout training, which is what let ESRGAN push texture sharpness further than SRGAN could.

3c — Perceptual loss on pre-activation VGG features

SRGAN computed its VGG content loss after the ReLU activation. Post-activation feature maps are sparse — roughly 11% of neurons are active at any given layer, since ReLU zeroes out everything negative. That throws away most of the signal a perceptual loss needs, especially for brightness/contrast matching. Pre-activation features are free to compute and strictly more informative.

3d — Network interpolation

Rather than training one PSNR-oriented and one GAN-oriented model and picking one, ESRGAN interpolates the weights of the two networks directly — a continuous dial between sharp-but-less-faithful and faithful-but-blurrier, with no retraining.

Relation to hallucination: 3b and 3c both make the same knob SRGAN introduced more powerful. This is the origin of the over-invention pole: to look convincing, the generator has to commit to one specific, detailed realization, whether or not it's factually correct. Hallucination risk in the ESRGAN lineage is not an accidental side effect — it's the deliberate, load-bearing cost of the fix for Section 2's blur.

04Real-ESRGAN (2021) — same generator, different data, sharper judge

Grounded

4a — Pixel-unshuffle (efficiency only)

Before the LR image reaches the RRDB trunk, it passes through a pixel-unshuffle operation that trades spatial resolution for channel depth — a pure compute/memory optimization that doesn't change what the trunk is capable of.

4b — High-order (second-order) degradation model

Real-ESRGAN's actual headline contribution. Rather than one clean blur→downsample→noise→JPEG pass, the same process is applied twice in sequence with independently randomized parameters, producing LR training images that statistically resemble real-world degraded images much more closely. Sinc filters are added specifically to reproduce ringing and overshoot artifacts — a signature of real sharpening/compression that the classical degradation model never produces, meaning a model trained without them has never seen that artifact type during training.

4c — U-Net discriminator + spectral normalization

ESRGAN's VGG-style discriminator collapses judgment into one scalar per image. Once training images carry much wider local degradation severity, that's too coarse. Real-ESRGAN's U-Net discriminator outputs a per-pixel realness map instead, giving the generator spatially localized feedback. This upgrade, combined with the harder task, increases training instability — hence spectral normalization, which constrains the discriminator's Lipschitz continuity and keeps gradients well-behaved.

Relation to hallucination: the generator's decision-theoretic behavior under ambiguity (Sections 2–3) is completely unchanged — same RRDB block, same loss family. What changes is (i) what counts as "ambiguous": a much wider range of real-world content now falls into the genuinely-uncertain zone, since training covers a much wider degradation distribution, and (ii) the discriminator is sharper and spatially local, so wherever the adversarial term dominates, invented detail is guided with per-pixel precision. Real-ESRGAN didn't change how hallucination happens — it changed how often it gets triggered and how locally precise it looks when it does.

05Resolved — what your own fine-tuning table already answers

Grounded — confirmed by report §07

I originally flagged this as an open question — but Section 07's own fine-tuning results table already answers it: every ESRGAN row lists L1 as its loss type, and every Diffusion row lists MSE. No adversarial or perceptual loss term is active during fine-tuning, for either model.

Consequence — ESRGAN
All 4 fine-tuned strategies sit purely on the under-invention pole

ESRGAN's over-invention capacity comes entirely from its discriminator/adversarial loss (Section 3). With fine-tuning using L1 only, none of the four fine-tuned checkpoints (full, partial, lora, head_only) have any active mechanism for hallucination in the SRGAN/ESRGAN sense. Whatever artifacts appear in the fine-tuned gallery — the farmland striping darkening under lora, the color shift under head_only — are a different mechanism: fine-tuning-induced distribution shift or undertrained partial capacity, not adversarial hallucination. Continued L1-only updates on top of a GAN-trained checkpoint could plausibly pull it further toward blur, not further toward invention — worth checking directly if you want to confirm.

Consequence — Diffusion
Over-invention capacity survives fine-tuning, unlike ESRGAN's

Diffusion's over-invention pole doesn't come from an adversarial loss term at all — it comes from the stochastic reverse-sampling process itself, which is architecturally present regardless of what loss trained the noise predictor. MSE-only fine-tuning trains the noise-prediction network, but doesn't remove the sampling mechanism that lets it commit to one specific plausible realization per draw. So the diffusion strategies keep their hallucination capacity through fine-tuning; the ESRGAN strategies effectively lose theirs.

This is worth a direct correction in §08 of the main report: the fine-tuned ESRGAN "hallucination analysis" subsection is very likely describing under-invention effects (distribution shift, capacity starvation) rather than hallucination proper, and the label should probably change.

06The unifying framework

Grounded

Both "hallucination" (inventing plausible-but-wrong content) and "under-texturing" (blurring away real content) are the same underlying event — a model resolving genuine output ambiguity — expressed in opposite directions depending on which loss terms and mechanisms are active.

Under-invention poleOver-invention pole (hallucination proper)
MechanismLoss-optimal output is the statistical average across all plausible outcomesModel must commit to one specific, convincing realization
Responsible termL1 / L2 pixel loss (SRGAN's starting point, still Real-ESRGAN's base term)Adversarial + perceptual loss (SRGAN/ESRGAN); in diffusion, the stochastic sampling process itself
Tell in the metricsBoth SSIM and PSNR suffer togetherLPIPS/SSIM can improve while PSNR drops
Example, this projectChaparral under-texturing; farmland comb-filter striping (SSIM 0.361 & PSNR 21.62 both weak)dense_residential_01's invented object (diffusion, zero-shot only — see §05)

This also fully resolves the farmland gap from the main report review: farmland's periodic field-boundary lines sit near the LR grid's sampling limit, creating the same kind of ambiguity as chaparral's texture — just from aliasing instead of semantics. ESRGAN's L1 term averages across plausible phases (the striping artifact, hurting both metrics); the diffusion model's stochastic sampling commits to one specific phase per draw, and on this scene, landed closer to the true one.
